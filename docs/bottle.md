旧脚本把 accessToken、time、mobileKey 写死，BoxJS 又只在字段缺失时初始化，导致旧值长期保留。旧脚本还会把不可解析的 HTTP 200 当成成功。新版删除内置凭证，严格检查 HTTP、JSON 和业务字段，并查询任务状态确认动作结果。

只读验证：原抓包的旧时间返回 `80021 / 请校准你的时钟`；仅改成当前时间而保留原 mobileKey 返回 `400 / 系统异常`。不能只改 time 冒充签名。mobileKey 的生成算法尚未取得，签名是否能够跨接口复用还没有手机端的端到端验证。

## 安装与凭证自动获取

1. 替换旧瓶子定时脚本，导入本仓库的 Loon 插件；不要同时保留两套瓶子任务。
2. 在 BoxJS 导入本订阅，或继续使用已更新的服务器综合签到订阅。
3. 打开 App 的签到/任务页。捕获规则会保存 accessToken、time、mobileKey、设备头，更新旧 `gzd_bottle_header_*` 键，但不会打印凭证。
4. 插件每分钟检查一次。只有 App 原始签名足够新鲜时才发请求；默认允许90秒、最多120秒。签名过期则静默等待，不伪造签名或反复弹通知。

**目前不具备全天离线、无人值守的签名刷新能力。** 打开 App 后才有机会执行自动任务。若服务端还绑定了路径或正文，现有签名复用也可能失败；脚本会停止并提示刷新，不报告成功。要实现无需打开 App 的定时任务，仍需合法可用的签名生成方法。

## 发布与回复内容

用户已选择自动执行花银币换瓶分任务。默认开关开启，但没有模板时不会发布。

发布：先在 App 中配置你愿意重复发送的内容并发布一次，捕获规则把这个 App 生成的加密 `s` 保存在设备本地。之后自动发布会复用这份模板，逐次核对进度，最多补齐3次。**BoxJS 无法把任意明文转换成加密 `s`，也没有从本次私人抓包预装发布内容。** 加密模板是否可跨请求复用尚未在线验证，失败时会停止。

回复：本次抓包没有真实回复请求。BoxJS 保留了 `reply_path`、`reply_cost` 和回复模板接口；它们未配置时只提示缺少数据，不使用推荐私信或打招呼冒充回复。需要补充一次“获取瓶子→回复瓶子→领取奖励”完整抓包，核对真实接口与成本后再配置，并在 App 中发送你希望复用的内容以捕获模板。单一回复模板也可能绑定某个瓶子/会话，不能据此保证回复5个不同瓶子。

已完成但尚未领取的任务会自动领奖，状态来自服务器：0=未完成、1=可领取、2=已领取。只处理任务ID 2/3/4，首充/购买任务不执行。任务3领奖路径根据同组任务ID规则构造，尚无任务3成功领取的抓包验证。

## 额度和防重复

- 默认每日自动支出上限65银币，最低保留100银币，可在 BoxJS 调整。按北京时间重置。
- 发布按本次抓包每次5银币计，打招呼每次50银币计；服务端将来改价时需复核。
- 未配置成本的回复不会执行。人工在 App 中的支出不计入自动额度，但动作前都会检查当前余额。
- 发出扣币请求前即在设备本地预留额度。超时/结果不确定不会自动重放同一动作，避免再次扣币。
- 成功与已签到都查询服务端状态，银币和瓶分分别统计。
- 仅缓存该 App 的必要请求头和明确的发布/回复模板，不保存其他聊天内容。

## 安装位置与排错

`.lnplugin` 是插件配置，开头是 `#!name`，必须在 Loon【配置→插件】添加，不能填进 JavaScript 脚本 URL。若报 `Invalid character: #`，请删除或停用那条误填插件地址的脚本，再从插件区安装。直接运行脚本时使用 `loon-bottle-checkin.js`，但只添加 JS 不会自动安装请求捕获规则。

打开 App 后查看 BoxJS 的【捕获状态】：为空表示请求没有进入捕获脚本；提示缺少头字段表示规则已命中但没有完整凭证；显示“已捕获完整凭证与签名”才具备执行前提。HTTPS 需要先启用 MitM 并信任证书，再重新进入 App 任务页。捕获状态不会保存真实 Token。

## 超时修复（2026-11-15）

Loon 的 $httpClient timeout 单位为毫秒，已由错误的12改成12000（12秒）。回归测试会检查每个请求的超时单位；手动运行捕获入口现在只提示打开 App，不执行任务。错误日志仅显示接口路径和错误码，不输出请求头或凭证。
