# GitHub Actions 自动签到失败重试

配置：`.github/workflows/sign-retry.yml`，监听 `Auto Sign Tasks` 在 main 分支的定时或手动执行结果。

- 只有 GitHub Actions 结论为 failure 才重试，成功和手动取消均不重试。
- 首次执行失败后最多重跑 3 次，总共最多执行 4 次。使用原 run 的 `run_attempt` 计数，重跑不会创建新的计数链。
- 第 4 次执行仍失败时，通过现有 Secret `BARK_URL_TIEBA_QIANDAO` 发出一次告警，随后结束本轮重试。下一天的定时任务仍照常执行。
- GitHub 查询/重跑 API 出错时停止自动操作并尝试 Bark 告警，避免状态不明时重复重跑。
- 告警接收失败也不会继续签到重试；守护工作流会显示失败。Bark API 接受不代表手机已显示通知。
- 独立守护工作流使用 runner 自带 Python，不依赖主任务的 setup-python 下载；不检出主任务代码或读取其产物。
- 此机制处理工作流失败（包括环境安装、依赖安装、提交等步骤失败）。原签到脚本仍保留原来的业务结果与退出码处理；如脚本吞掉错误或以退出码 0 返回，工作流会显示成功，此机制不会据此重跑。

验证：YAML 解析、内嵌 Python 编译、8 项模拟测试覆盖 1/2/3 次失败重跑、第 4 次停止告警、过期事件、成功状态、缺失 Bark 配置、Bark 请求失败与敏感 URL 不进入日志。模拟测试没有发送真实通知。
